# SynapseX Self-Run and Defensive Security Policy

SynapseX is a **generation and guidance** product. Its normal result is a set of downloadable files, copyable commands, verification steps, and rollback guidance. A command is never considered completed merely because it was generated, copied, or downloaded.

## Authorized targets only

The user must own, administer, or have explicit written authority for every project, server, folder, removable drive, device, account, or company environment named in a request. SynapseX must not be used to bypass locks, root or jailbreak devices, access another person’s data, extract credentials, disable protective controls, install covert monitoring, or attack systems.

## Self-run is the default

The product does not require a remote runner for normal use. The user reviews generated artifacts, saves them locally, runs the declared preflight, and then runs the selected commands. An optional runner may exist later for managed organization workflows, but it must never be required to receive the complete self-run package.

## Free-first behavior

SynapseX must supply deterministic target contracts, preflight artifacts, installation checklists, verification steps, and defensive templates without a paid provider being compulsory. For a truly open-ended custom codebase, a model is still required: the user may connect an approved local open-source model or choose an optional configured model. The product must state this honestly and must not pretend a generic scaffold is a complete custom application.

## Risk tiers

| Risk | Examples | Required behavior |
|---|---|---|
| Low | Generate website skeleton, Python utility, read-only project inspection | Return files, preflight, and verification. |
| Review | Install a local dependency, create a service, publish a local build | Explain prerequisites and require review before commands. |
| Critical | Encryption, removable-drive changes, firewall/system policy, permissions, device configuration | Require owner-authorized target confirmation, backup/recovery guidance, command preview, verification, and rollback. |
| Blocked | Lock bypassing, rooting/jailbreaking, credential theft, covert persistence, disabling endpoint protection, unauthorized access | Refuse and provide a safe lawful alternative where appropriate. |

## High-impact safeguards

Critical actions require a target selection, an owner-authorized confirmation, a visible action summary, and a reversible plan where technically possible. The generated command package should never silently format, wipe, encrypt, repartition, delete, deploy, or change a security policy. It should first provide discovery/preflight, then ask the user to confirm the exact target before giving a final change command.
